# 新规则三步校验法

> 借鉴 label-audit-kb 项目（2026-08-03），防止拍脑袋加规则导致误判。
> 适用于：新增 R 系列校验规则 / 新受控词 / 新阈值 / 新分类逻辑。

---

## 三步校验（不通过不写入）

| 步骤 | 操作 | 验证标准 | 举例 |
|---|---|---|---|
| 1. 溯源 | 规则必须能引用到具体依据 | 业务口径/用户确认/单证字段，不能靠常识 | R2 启运国≠原产国 → 依据 26B 检疫证实测 |
| 2. 验算 | 数值/清单逐条对照真实单证 | 发现任意一条不合规→方案废弃重来 | R3 双厂 → 数检疫证生产厂家个数 |
| 3. 回测 | 用最近 3 票已整理单证测误报 | 误报率>0→不入库先修正 | 新规则跑 26A-01/03/06 看会不会误报 |

## 案例（本项目的教训）

- 26A-06：曾因"只 OCR 第1页"漏判提单/产地证/卫生证 → 新增页级索引器，回测通过才采用。
- 分类误判：报关单被内容规则误归"检疫证明"（因含检验检疫字样）→ 改为文件名优先+回测。

## 两条底线（不矛盾）

- **整理执行底线**：宁可多标"待人工"，不可漏（漏的代价是单证错位）。
- **知识库写入底线**：不确定不入库，入必准确（假规则造成系统性误判，比单次误判严重得多）。

## 什么时候跑三步

1. 用户提出新校验需求时
2. 发现新的供应商易错点时
3. 修改 config/rules.yaml 或新增受控词时
4. OCR 识别率调整（预处理/分块阈值）时
