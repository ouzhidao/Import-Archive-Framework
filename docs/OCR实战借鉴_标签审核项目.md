## 三、分块护栏（默认不分块，但保留完整备用方案）

### 默认策略
- 本项目**默认整页 1 次 OCR，不分块**（页=1 次调用）——避免标签项目的分块 bug
- 缩图到 3.9MP 内再 OCR，1 次调用（已固化进 `ocr_vision.py` 的 `_resize_to_max_px`）

### 备用分块方案（未来某文件必须分块时启用，已固化进 `ocr_vision.py` 的 `tile_split`）

**触发条件**（自动，借鉴标签项目）：
1. 缩图 OCR 未通过质检（关键字段缺失/分辨率不足）
2. 编号位数异常（如报关单号位数不对）

**分块参数**（保完整性核心）：
| 参数 | 值 | 作用 |
|------|-----|------|
| 单块 ≤ 4MP | `tile_w × tile_h ≤ 3_900_000` | 满足百度单图上限 |
| **块间 10% 重叠** | 相邻块重叠 10% 边界 | **边界文字不被截断**——这是完整性的关键，正是标签项目审核不准的根源之一 |
| 合并去重 | 重叠区文本按行去重 | 避免重复字 |
| 护栏 | `cols×rows ≤ 50`，超则中断 | 防分块数 bug 撑爆额度（660块教训） |

**分块公式**（不用 stride！）：
```python
import math
MAX_PX = 3_900_000
aspect = w / h
tile_h = int(math.sqrt(MAX_PX / aspect))
tile_w = int(MAX_PX / tile_h)
cols = math.ceil(w / (tile_w * 0.9))   # 0.9 = 留 10% 重叠
rows = math.ceil(h / (tile_h * 0.9))
if cols * rows > 50:
    raise RuntimeError("分块数异常 >50，中断防配额浪费")
```
> 关键：`cols = ceil(w / (tile_w * 0.9))` 用重叠后的有效步进，而不是 stride 公式（标签项目 bug 就出在这）。

**边界处理**：重叠区文本合并时，按"该行中心是否在新块有效区内"去重，保每字只出现一次。

## 十一、页级索引器（M3 增强，防多页PDF漏单证）

> 2026-08-03 新增。解决"七八十页PDF只OCR第一页漏单证"的问题。

### 原理（先零成本扫描，再按需OCR）

```
输入 PDF → build_page_index()（pdfplumber/fitz，0成本）
  逐页: 有文本层? 前80字符? → 页类型识别
→ 决策:
  ├─ 全文本层      → 0 OCR（全读）
  ├─ 单页单证      → 只OCR第1页
  ├─ 多页合并件    → full_ocr（全扫，防漏单证）
  └─ >30页超长     → 抽样首/中/尾，不全扫
```

### 成本核算（百度OCR 2000次/月）
| 情况 | OCR调用 | 占比 |
|---|---|---|
| 电子版多页（有文本层） | 0 | 0% |
| 扫描件合并件（真全套） | N页 | 可接受（必要） |
| 扫描件超长（>30页） | 抽样3-5 | <0.5% |
| 普通单证 | 1-2 | <0.1% |

### 关键收益
1. **防漏单证**：26A-06 的 13 页"全套单据"若用旧方法只OCR第1页，会漏提单/产地证/卫生证；页级索引器自动发现合并件+8页扫描件需全扫
2. **文本层零成本**：电子版多页全读不耗额度
3. **自动按页拆分**：每页类型识别后可直接拆出独立单证
4. **超长保护**：防一次性耗尽额度

### 使用
```python
from scripts import ocr_vision as ov
idx = ov.build_page_index(pdf_path)      # 零成本页索引
res = ov.ocr_pages_with_index(pdf_path)  # 按需OCR + 页类型
```
