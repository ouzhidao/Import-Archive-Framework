## 三、合并架构建议（短期不做，先留接口）

两个项目同源（都是"供应商来文件→整理→归档→人确认"），合并架构：

```
共用层（可合并）：
  - HTML查看器模式（html_report.py 骨架） → 两个项目都生成总览HTML
  - 微信采集（wechat_scan.py + .dat解密） → 收单统一入口
  - OCR/图片处理（缩图/质检/预处理/三级去重） → 共享pipeline
  - 无后台确认闭环（导出json→回写） → 代理确认统一机制
  - 配置化（paths.yaml/rules.yaml） → 统一

差异层（各保留）：
  - 数据模型：标签库用"物料→版本链→槽位"，单证用"L1-L4→票→单证类型"
  - 业务规则：标签GB法规 vs 单证报关/检疫
  - 产出：标签审核报告 vs 进口单证统计

合并方式：抽公共pipeline为独立包（ingest/ocr/dedupe/viewer/confirm），
  两项目各自保留 config + 数据模型 + 领域规则。
```
