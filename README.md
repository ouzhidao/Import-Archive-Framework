# 进口单证归档框架（方法论 · 可推 Git）

> 进口鱼糜/鱼片单证自动化整理框架。**本仓库只存方法/规范/脚本/模板**；真实业务单据留本地，永不进 Git。
> 数据边界见 `.gitignore` 与 `AGENTS.md`。

## 目录

| 目录 | 内容 | 进 Git |
|---|---|---|
| `AGENTS.md` | **项目宪法（通用，必读）**：铁律+架构+业务口径+接手/复核 | ✅ |
| `config/` | 业务规则配置（供应商/单据/路由/规则/路径） | ✅ |
| `scripts/` | 管线模块（OCR/归票/索引/校验/落盘/去价/查看器） | ✅ |
| `docs/` | 命名规范 / 项目状态与恢复 / 借鉴与前瞻 | ✅ |
| `schema/` | 索引卡 JSON Schema（**预留，当前为空**） | ✅ |
| `templates/` | 审核初稿模板（**预留，当前为空**） | ✅ |
| `runtime/` | **运行时数据**（真实单证/索引卡/缓存/统计/样本） | ❌ |
| `.env` | 密钥（百度 OCR 等） | ❌ |

## 快速开始

1. 读 **`AGENTS.md`**（铁律 + 架构 + 运行 + 业务口径；`CLAUDE.md` 仅为其指针）
2. 读 `docs/项目状态与恢复.md`（最新进展 / 待办 / 已知遗留）
3. 复制 `.env.example` 为 `.env` 填百度 OCR 密钥（A主/B备）
4. `python scripts/ocr_vision.py <pdf>` 验证 OCR
5. `python scripts/ticket_overview.py` 生成票总览 HTML 查看器

## 核心文档

- `docs/Git与本地分工.md` — **Git 层 vs 本地层清单**（交接/换机必看：哪些进 Git、哪些留本机）
- `AGENTS.md` — **项目宪法（必读）**，含业务口径：日期/发票明细/捕捞区域/必备矩阵/报关单双角色/R7/捕捞证核对锚点
- `docs/命名规范.md` — 命名铁律（L4/文件名/友好标签/号码/报关单角色）
- `docs/项目状态与恢复.md` — 进展、待办、规则定型过程、捕捞证核对实例
- `docs/OCR实战借鉴_标签审核项目.md` — OCR 防坑（缩图/质检/配额/页级索引）
- `docs/统计表设计.md` / `docs/新规则三步校验法.md` / `docs/草稿审核工作流_前瞻设计.md`
- `docs/ARCHITECTURE.md` — **历史初版架构**（旧命名，仅存档参考；以 `AGENTS.md` 为准）
- `config/*.yaml` — 全部业务规则（改规则不改代码）

## 人侧界面（票总览 HTML）

- 数据源：`runtime/tickets/*_index.json` → `scripts/ticket_overview.py` → 自包含 HTML
- 分层筛选 + 供应商/物料/年份 + 关键词搜索 + 发票明细 + 生产日期/捕捞区域 + 定位目录

## 数据红线

真实单据只读不写、只复制不移动、小批量落盘；真实税号/账号永不写入；数据层永不进 Git。
